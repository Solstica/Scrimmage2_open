# 论文模块化协作规范（必须遵守）

## 1. 核心规则
不要再创建或维护一个包含全文正文的 `document.tex` 作为日常编辑入口。
全文只能由各模块正文拼装生成；总论文文件只负责调用模块、统一格式和编译。

## 2. 每个人应该改哪里
- 摘要：`modules/00_abstract/paper/abstract.tex`
- 问题重述：`modules/10_restatement/paper/restatement.tex`
- 符号说明：`modules/11_notation/paper/notation.tex`
- 模型假设：`modules/12_assumptions/paper/assumptions.tex`
- 问题一：`modules/20_q1/paper/q1.tex`
- 问题二：`modules/30_q2/paper/q2.tex`
- 问题三：`modules/40_q3/paper/q3.tex`
- 模型评价：`modules/50_evaluation/paper/evaluation.tex`

公共入口、class、preamble、全文 wrapper 只由整合负责人维护：
- `paper/main.tex`
- `paper/paper_template.tex`
- `paper/preamble.tex`
- `paper/cumcmthesis.cls`

## 3. 禁止事项
1. 禁止把 Q1/Q2/Q3 正文复制进新的总 `document.tex` 再独立修改。
2. 禁止在模块正文里重复添加由总入口负责的顶级标题，例如 `\section{模型假设}`。
3. 禁止删除模块的 preview 入口。
4. 禁止把某一问的图表和数据放进根级临时“论文汇总”目录作为唯一版本。
5. 禁止为了排版方便在论文分支里改算法结果、冻结数值或模型路线。
6. 禁止把旧路线图直接配到新路线正文中；旧 Origin 图可以保留，但必须先更新数据和逻辑。

## 4. Preview 的正确用法
Q1/Q2/Q3 均有独立 preview。日常写作先编译本问 preview，不需要把全文复制到一个文件里。
正文变更只改 `q1.tex/q2.tex/q3.tex`；preview 自动输入正文。

整合负责人再在临时 merge worktree 中编译全文。

## 5. 注释槽位
类似下面的注释是协作定位标记，不会出现在 PDF 中，禁止随意删除：
```tex
% <ABS:INTRO>
...
% </ABS:INTRO>
```
修改内容时改标记之间的文字，不改标记本身。

## 6. 图表规则
- PNG/PDF：用于论文显示；
- Origin `.opju/.opj`、Excel `.xlsx`：用于后续可编辑；
- 两者都应进入对应问题模块；
- 即使当前数据是旧路线，只要图形模板有价值也可保留，但必须明确标记 TODO，未更新前不得作为最终证据图。

## 7. Git 分支
论文手不要提交到 main，也不要重新建立一个“全文总稿开发分支”代替模块分支。
按任务进入对应 feature 分支；公共排版变更交给 `feature/paper-common-final`。

## 8. 提交前自检
- 只改了自己负责的模块？
- 是否误加了重复 `\section`？
- 是否保留 preview？
- 是否保留协作注释槽位？
- 图与正文数值是否一致？
- `git status` 是否没有无关文件？

任何一项不确定，先不要 push。
